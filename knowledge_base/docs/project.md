# 项目长期定义

本文件保存相对稳定的项目定义。当前任务、临时验收条件和测试历史不在这里维护。

## 1. 项目目标

把邮件中分散的高价值文章整理成个人网页知识库，让用户可以通过邮件接收日期或内容主题重新发现、理解和使用这些信息。

知识库以文章为最小知识单元。邮件只提供文章进入知识库的日期，不作为独立业务对象保存。

如果现有邮件项目已经对文章完成 AI 提取和概括，知识库可以复用这些文章级结构化字段；邮件正文、邮件主题、发件人和邮件 ID 仍不进入知识库持久化数据。

## 2. 用户与成功结果

### 用户

- 单个个人用户；
- 主要阅读 AI 模型、产品、Agent、工作流、商业和职业变化相关内容；
- 希望减少逐封邮件、逐个网页打开和重复理解的成本。

### 成功结果

- 能快速看清最近一段时间收集了哪些内容；
- 能按邮件接收日期、分类、标签和关键词定位文章；
- 每篇文章具有足够的中文摘要和来源信息；
- 能从知识库进入原始网页继续阅读；
- 已读和收藏操作足够简单；
- 日常使用不需要维护复杂基础设施。

## 3. 系统边界

### 包含

- 文章记录；
- 邮件接收日期；
- 邮件项目已产出的文章级结构化内容；
- 按需网页正文提取；
- 中文摘要和关键观点；
- 主分类与基础筛选标签；
- 日期浏览、筛选、搜索和文章详情；
- 已读与收藏；
- 独立的数据更新与失败记录。

### 不包含

- 修改或替代现有邮件发送流程；
- 完整邮箱备份；
- 邮件客户端功能；
- 邮件主题、发件人、邮件 ID 或邮件正文的持久化；
- 一篇文章与多期邮件之间的关系；
- 多用户、团队协作、角色权限或 SSO；
- 企业级高可用、微服务和分布式基础设施；
- 未经用户确认的公开部署。

## 4. 与现有邮件项目的关系

```text
现有信息源
    ├──> 现有邮件流程 ──> Gmail / Notion（保持不变）
    └──> 独立知识库流程 ──> 个人知识库
```

知识库不得成为邮件发送的前置依赖。知识库处理失败时，现有周报仍应正常生成、发送和归档。

现有邮件项目可以作为知识库的上游文章来源：它负责发现链接，并可输出文章级结构化结果。知识库通过 `canonical_url` 接收、去重和复用这些结果；不保存邮件正文，也不建立邮件对象。

## 5. 核心流程

```text
识别待收录文章
    ↓
记录 email_received_at，并接收已有文章级结构化字段
    ↓
规范化文章链接并检查唯一性
    ↓
复用已有 summary_zh / key_points / primary_category
    ↓
对缺失或低置信度文章按需提取网页正文和元数据
    ↓
仅对缺失字段调用 AI 补齐
    ↓
保存文章数据
    ↓
生成可浏览和搜索的个人网页
```

## 6. 技术架构

### 数据处理层

- Python：采集、导入、解析、规范化、缺失补齐和页面生成；
- requests：网页请求；
- Trafilatura：按需网页主体和文章元数据提取；
- Gemini：仅对缺失结构化字段进行摘要、关键观点和分类补齐；
- 单篇处理失败不得终止整个批次。

### 数据层

- 最近三周对应的 3 封真实周报邮件提取出的本地 JSON 数据用于界面原型和自动测试；
- 测试数据文件保留在本地并排除 Git 提交；
- SQLite 用于正式个人知识库；
- `canonical_url` 用于唯一性判断；
- 不引入 PostgreSQL、Redis、消息队列或独立搜索服务。

### 展示层

- Jinja2 生成网页；
- 原生 HTML、CSS 和少量 JavaScript；
- 浏览器端完成筛选与轻量搜索；
- 已读和收藏最初保存在浏览器 `localStorage`；
- 默认优先支持本地访问。

## 7. 核心数据对象

### Article

知识库的最小业务对象。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string | 是 | 稳定唯一标识 |
| `email_received_at` | datetime | 是 | 唯一保留的邮件数据 |
| `canonical_url` | string | 是 | 清理跟踪参数后的原文地址 |
| `title` | string | 是 | 文章标题 |
| `author` | string/null | 否 | 文章作者 |
| `source` | string | 是 | 网页或内容来源名称 |
| `source_type` | enum | 是 | 来源类型 |
| `published_at` | datetime/null | 否 | 网页文章自身的发布时间，不属于邮件数据 |
| `summary_zh` | string | 是 | 中文摘要 |
| `key_points` | string[] | 是 | 关键观点 |
| `why_it_matters` | string/null | 否 | 历史兼容字段，后续默认不生成 |
| `primary_category` | enum | 是 | 唯一主分类 |
| `tags` | string[] | 否 | 基础筛选标签，F-017 不生成内容标签 |
| `value_score` | integer/null | 否 | 历史兼容字段，后续默认不生成 |
| `content_status` | enum | 是 | `complete`、`email_only` 或 `failed` |

### UserState

个人阅读状态，不改变文章内容。

| 字段 | 类型 | 说明 |
|---|---|---|
| `article_id` | string | 对应文章 |
| `is_read` | boolean | 是否已读 |
| `is_favorite` | boolean | 是否收藏 |
| `updated_at` | datetime | 最后更新时间 |

### ProcessingRun

记录一次独立处理任务的结果，不保存邮件正文。

| 字段 | 类型 | 说明 |
|---|---|---|
| `run_id` | string | 执行编号 |
| `started_at` | datetime | 开始时间 |
| `finished_at` | datetime/null | 完成时间 |
| `success_count` | integer | 成功数量 |
| `failed_count` | integer | 失败数量 |
| `result` | enum | `success`、`partial` 或 `failed` |

## 8. 数据约束

1. `email_received_at` 必填，并作为默认时间浏览依据。
2. 每篇文章只能有一个 `email_received_at`。
3. 不建立独立邮件对象或文章与邮件的关联表。
4. `canonical_url` 在知识库中必须唯一。
5. 同一 `canonical_url` 对应不同邮件日期时必须记录数据冲突，不能静默覆盖。
6. 每篇文章只有一个主分类；标签仅作为基础筛选兼容字段，不作为 F-017 的 AI 生成目标。
7. AI 处理失败时必须保留可用的基础文章数据和失败状态。
8. 用户阅读状态不得写回或改变 Article。

## 9. 分类体系

### 主分类

每篇文章必须选择一个：

1. 模型与平台
2. Agent 与自动化
3. AI 产品与工具
4. 商业、创业与投资
5. 工作方式与职业变化
6. 工程、基础设施与安全
7. 研究、政策与行业趋势
8. 待人工确认

### 来源类型

- Newsletter
- 个人博客
- 媒体
- 公司或工程博客
- 投资机构
- 研究或政策机构
- 其他

### 标签

标签为开放列表，但当前正式阶段不由 AI 自动生成新的内容标签。主分类、来源类型和标签是三个独立维度。

## 10. 高层功能路线

1. 建立最近三周 3 封真实周报邮件文章的可验证测试数据；
2. 建立日期浏览；
3. 建立分类、标签与关键词检索；
4. 建立文章详情、已读和收藏；
5. 完成桌面与手机可用性验证；
6. 接入现有邮件项目的文章级结构化输出；
7. 完成链接规范化、去重和结构化字段复用；
8. 建立按需正文提取；
9. 对缺失结构化字段接入 AI 补齐；
10. 使用 SQLite 持久化；
11. 建立独立更新机制。

每一步的具体实现和验收条件只在成为当前任务时写入 `current-task.md`。

## 11. 已确认决策

- 知识库与现有邮件工作流隔离；
- 先验证用户体验，再逐步接入真实数据处理；
- 采用个人级、低维护技术架构；
- 邮件数据只保留 `Article.email_received_at`；
- 邮件项目已有文章级 AI 结果时，知识库优先复用，不默认重新概括；
- 网页正文提取是按需补充能力，不再作为所有新增文章的强制前置步骤；
- 视频类网页不要求 AI 看完视频；缺字段时默认跳过并标明视频类，除非未来单独建立视频转录处理任务；
- 不建立邮件业务对象；
- 不支持一篇文章关联多期邮件；
- 不默认生成 `why_it_matters`、`value_score` 或新的内容标签；
- `AGENTS.md` 只承担永久规则和文档路由；
- 当前工作只在 `current-task.md` 中定义；
- 测试和重复错误在 `test-log.md` 中追加保存。
