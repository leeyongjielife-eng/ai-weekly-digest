Secret protection must scale with software

来源：github.blog 主分类：工程、基础设施与安全 收录日期：2026-10-12 05:22

文章概要

GitHub 产品经理基于九个季度的数据指出，AI 代理参与代码提交的比例从一年前的不足 10% 升至三分之一，但开发者并未变得更粗心，而是被开发速度甩在身后；因此平台必须承担更多防护工作，通过上下文感知分类器在推送前拦截更多密钥泄露，减少对人工响应的依赖。

关键观点

  • GitHub 上三分之一的 pull request 已涉及 AI 代理，一年前不足十分之一；若趋势延续，两年内大部分推送到 GitHub 的代码可能由代理编写，且很多代码可能永远不会被人类完整阅读。
  • 九个季度数据显示，筛查推送量增长 2.84 倍、携带凭据的推送增长 2.59 倍，但每次推送的泄露普遍率没有统计上可检测的趋势；开发者覆盖推送拦截的比例从 6.63% 线性降至 3.93%，说明开发者更理解风险而非更粗心。
  • 人工撤销泄露密钥的平均时间约 40 天，约五分之一超过 90 天；在代码创建加速而人工修复无法同步扩展的情况下，平台必须提前预防更多泄露并降低剩余事件的人工处理量。
  • GitHub 与微软应用科学团队构建的 ModernBERT 分类器可在不到两毫秒内评估一批候选密钥，精度高于现有基于 LLM 的流水线且成本极低，有望将可预防的密钥数量翻倍以上，并已扩展到 Copilot CLI 和 Copilot App 的 /security-review 命令。
