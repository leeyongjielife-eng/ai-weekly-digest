Project HydraFusion: Frontier quality via multi-model orchestration

来源：github.blog 主分类：模型与平台 收录日期：2026-09-07 03:57

文章概要

GitHub 推出 Project HydraFusion 研究预览，通过运行时多模型编排为 Copilot 提供前沿级编码能力。它把工作流选择当作优化问题，在单模型、级联、评审三种执行模式间自适应选择，在多个基准上以显著更低的估算成本达到或接近 Opus 5 的质量。

关键观点

  • HydraFusion 将多模型编排从开发者手动操作搬进运行时：用户像选普通模型一样选择它，系统在后台根据推理、代码生成、调试、工具使用等能力信号，自动选择最省成本的执行路径。
  • 当前有三种执行模式对应不同质量-成本权衡：Single 用于单模型可直接解决的任务；Cascade 让高效模型先试，未过验收门槛再升级到更强模型；Critique 引入独立模型评审，适合评审比再次尝试更有用的任务。
  • 在 TerminalBench 2.1 上，HydraFusion 相比 Claude Opus 5 将验证任务质量提升 4.9 个百分点，同时估算成本降低 67%；在 DeepSWE 上质量差距 1.5 个百分点、成本降低 36%；在内部 CheckpointBench 上质量差距 0.1 个百分点、成本降低 65%。
  • HydraFusion 用 beam search 自动构建路由决策策略，而非手动调阈值，并在 TerminalBench 2.1、DeepSWE、CheckpointBench 三个基准上反复优化；当前预览最适合单轮、范围明确的编码任务，多轮长会话性能是下一步重点。
