Qwen 3.8 27B is excellent, but it defaults to wildly overthinking things

来源：simonwillison.net 主分类：模型与平台 收录日期：2026-08-17 01:39

文章概要

Qwen 3.8 27B模型在本地硬件上表现出色，但默认的“xhigh”推理设置会导致过度思考，建议用户改用低推理或无推理模式以获得更佳体验。该模型在生成SVG图像、边界框标注和驱动编码代理等任务上表现优异，但需注意其默认设置可能影响效率。

关键观点

  • Qwen 3.8 27B 默认 reasoning_effort 为 xhigh，导致在消费级硬件上严重过度思考：简单提示词也会消耗数万推理 token，例如画一个圆生成了复杂动画，画鹈鹕骑自行车耗时 21 分钟、消耗 22,276 推理 token。
  • 作者建议忽略默认设置，初次使用时应将 reasoning 调至 low 或关闭；关闭推理后同一鹈鹕 SVG 任务仅需 137 秒、3,715 token，但复杂工具生成任务（如边界框标注 HTML 页面）关闭推理后会出现坐标错位，说明推理在编码类任务中仍有价值。
  • 该模型在视觉任务上表现突出：能准确返回 0-1000 尺度的鹈鹕边界框 JSON，并能根据单条提示词生成完整的边界框可视化 HTML 工具，甚至自行添加了未要求的演示场景。
  • 本地 27B 模型已具备驱动编码 Agent 的能力：作者用 Pi 配置 LM Studio 上的 Qwen 3.8 27B，成功完成代码库问答和 JSONL 转 Markdown 脚本的编写与测试，但生成速度仅 15-30 token/秒，远慢于托管 API 模型（如 OpenAI 5.6 Sol 的 74 token/秒）。
