# Agent Instructions

## 权威性

本文件是知识库项目的唯一工作入口。开始任务时先读取本文件，再按任务类型读取指定文档；不得默认读取 `docs/` 下的全部文件。

## 永久边界

- 默认只修改 `knowledge_base/` 内的文件。
- 不修改现有邮件发送脚本及工作流。
- 知识库故障不得影响邮件发送。
- 项目只服务一个个人用户，不采用企业级架构。
- 邮件数据只保留 `Article.email_received_at`。
- 不建立邮件对象或文章与多期邮件的关系。
- 一次只实施一个功能，测试通过后才能开始下一功能。
- 不提交密钥、真实邮件正文或隐私数据。

## 文档路由

| 任务 | 读取内容 |
|---|---|
| 理解目标、架构、数据对象 | `docs/project.md` 对应章节 |
| 实施当前功能 | `docs/current-task.md` 的任务索引和唯一未完成任务章节 |
| 测试当前功能 | `docs/current-task.md` + `docs/test-log.md` 顶部索引 |
| 排查错误 | `docs/test-log.md` 中对应 `ISSUE` 章节 |
| 修改用户使用说明 | `README.md` |
| 改变项目架构或范围 | `docs/project.md`，并先获得用户确认 |

## 执行流程

1. 从 `docs/current-task.md` 的任务索引确认唯一未完成任务，只读取该任务章节。
2. 读取该任务指定的补充章节。
3. 实施当前任务，不扩展范围。
4. 执行规定测试，将结果追加到 `docs/test-log.md`。
5. 测试未通过时不得切换任务。
6. 测试通过并完成人工验收后，将任务标记为已完成并保留原记录，再写入下一任务。

已完成任务不得删除或覆盖；只有回溯问题时才读取其历史章节。

## 重复错误规则

- 第一次：记录并诊断。
- 第二次：不得原样重试，必须比较两次证据。
- 第三次：暂停实施，复审当前技术方向。
